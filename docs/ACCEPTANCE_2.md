## Не реализовано без согласования

**c) Статус `cancelled` в Lemon Squeezy.** `ends_at` подписки нигде не хранится
(ни в схеме `businesses`, ни в обработчике webhook), поэтому по условию задачи я не
реализовывал. Сейчас поведение такое: как только приходит `cancelled`, закрываются
outreach (`PAID` в планировщике), контакты (`status != 'active'`), поиск (`can_search`),
а checkout отвечает 409. То есть клиент теряет доступ в день отмены, хотя оплатил месяц.

Варианты:

1. **Без миграции.** При применении снимка подписки писать в `log` строку
   `event='subscription_ends_at'`, `detail=<ends_at ISO>` (при `resumed`/`active` писать
   пустое значение). Доступ вычислять функцией `billing.entitled(business, now)`:
   `active|on_trial`, либо `cancelled` и последнее `ends_at` в будущем. Плюс: схема и
   импортёр не меняются. Минус: `log` не предназначен для хранения состояния, нужен
   дополнительный запрос на каждую проверку.
2. **Минимальная миграция (рекомендую).** `migrations/004_subscription_ends_at.sql`:
   `ALTER TABLE businesses ADD COLUMN subscription_ends_at TEXT;` (nullable, UTC ISO).
   Webhook записывает `attributes.ends_at` (с проверкой на aware-дату, иначе NULL) в той
   же транзакции, что и статус; `resumed`/`active` очищают его. Одна функция
   `billing.entitled(business, now)` вместо четырёх разрозненных проверок: планировщик
   (outreach и poll), контакты, `can_search`, `require_search`. Если `ends_at` пуст при
   `cancelled`, доступ закрыт. Заодно закрывается случай потерянного webhook
   `subscription_expired`: после `ends_at` доступ закрывается по времени. Нужны тесты:
   до `ends_at` доступ есть, после нет, resume, пустой `ends_at`, Starter/Pro.
   По контракту смена схемы сопровождается пометкой в описании PR; импортёр
   (`scripts/import_from_railway.py`) трогать не нужно, колонка допускает NULL.

Прошу решить, какой вариант делать.

## Найдено и исправлено

**Нельзя заново оформить подписку после `cancelled`, если `subscription_expired` потерян.**
Воспроизведено: статус `cancelled`, `ends_at` в прошлом: доска показывает «Start your
subscription», но `POST /billing/checkout/{plan}` отвечает 409 «A subscription already
exists». Кроме того, вебхук `subscription_created` с новым id подписки игнорировался,
пока статус не `expired`, то есть даже после оплаты доступ бы не открылся. Исправление в
`app/billing.py`:
- checkout блокируется только при `on_trial` или пока `entitled()` (то есть `active` либо
  `cancelled` внутри оплаченного периода);
- новая подписка заменяет старую, если старая `expired` либо `cancelled` с истёкшим
  `ends_at`. Внутри оплаченного периода замена по-прежнему игнорируется.

Тесты `tests/test_lapsed_resubscribe.py` (8 штук): без исправления падают 3.
