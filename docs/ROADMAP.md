# Дорожная карта «Топор» — ноябрь 2026

Решение владельца, 3 ноября 2026. Порядок жёсткий: следующий шаг не начинаем, пока у текущего не закрыт «готово, когда».

## Шаг 1. Упрощаем проект до состояния топора — `evorove_lite`

Цель: продукт делает **то же самое для клиента**, но это одна программа, а не три сервиса.

Было: ~65 000 строк, 3 сервиса (engine, crm, lead) с HTTP между ними, 3 Postgres (~45 таблиц), SearxNG, React-сайт со сборкой, SMS/WhatsApp/календарь/сметы/LoRA/теневые воркеры.

Станет: 1 процесс Python, 1 файл SQLite (+ Litestream → Cloudflare R2), Claude API с веб-поиском вместо SearxNG, HTML-страницы с сервера вместо SPA, планировщик внутри процесса, stdlib smtplib/imaplib. Цель по размеру: **≤ 3 000 строк своего кода** (без тестов), **≤ 150 МБ RAM**.

Что должно работать точно так же:
1. Сайт evorove.com: лендинг, FAQ, Terms/Privacy, регистрация, вход, сброс пароля.
2. Подписка через Lemon Squeezy (Starter/Pro), вебхук. Тестовые оплаты включают тариф только для адресов из белого списка.
3. Доска владельца: Cold → In progress → Offer made → Done, справа переписка с человеком.
4. Поиск: ежедневно + кнопка «Find people». Только американский B2B, только человек с причиной (боль + дословная цитата + ссылка-источник) и email на сайте компании.
5. Первое письмо уходит само: «сначала боль, потом касание». Без цены, скидок и гарантий, которых нет в материалах.
6. Ответ по IMAP продолжает ту же карточку. Следующий ход выбирает политика продаж, формулирует Claude.
7. Оффер со ссылкой на оплату → карточка Offer made. Done только по факту записанной оплаты.
8. Защиты рассылки: ссылка отписки, почтовый адрес (CAN-SPAM), стоп-лист, тихие часы, дневной лимит (старт 20), SMS холодным никогда.
9. Ежедневная сводка владельцу в Telegram.

Что НЕ переносим в v1: SMS/Twilio, WhatsApp, календарь и брони, сметы/quotes, виджет-чат на сайте, companion LoRA и обучение, теневые воркеры, 2FA (вернём позже), Google Calendar.

Готово, когда: владелец прошла путь клиента на тестовом аккаунте локально и на staging; все тесты защит рассылки зелёные; `ps`/`docker stats` показывает ≤ 150 МБ.

Промпты: `docs/agent-prompts/axe/` (00 — общий контракт, 01–03 — по агенту, 04 — приёмка).

## Шаг 2. Переезд на свой сервер

Сервер: JustHost, Амстердам, 1 vCPU / 1 ГБ / 20 ГБ NVMe, Ubuntu 24.04 (212.192.20.133, оплачен до 19.01.2027). Запасной: Oracle Always Free (ARM 2 OCPU / 12 ГБ). Вход: Cloudflare Tunnel. Бэкап: Litestream → R2 (непрерывно). Почта: Zoho Mail Lite, SMTP 587.
Развёртывание топора: `git pull && systemctl restart evorove` + `cloudflared` как systemd-сервис. Без Docker.
Перенос данных: бизнес клиента 0, его DNA/оффер/материалы, аккаунты владельца, стоп-лист, история карточек — скриптом из Postgres Railway в SQLite.
Если 1 ГБ окажется мало (OOM дважды) — OVH VPS-1 (2 vCPU / 4 ГБ, ~$4.54/мес), та же установка.
Готово, когда: evorove.com работает с нового сервера неделю без падений, Railway выключен.
Детали инфраструктуры: `docs/agent-prompts/migration-evorove-vps-2026-11.md` (части про Docker/Postgres/Coolify заменены этим планом — для топора они не нужны).

## Шаг 3 и дальше. Чиним и прокачиваем лидов

3. Пробный поиск без писем: 20 компаний, владелец смотрит таблицу (компания, штат, человек, роль, боль, цитата, источник) и правит бриф.
4. Репетиция продажи на ящике владельца: Cold → письмо → ответ → оффер → оплата → Done.
5. Боевой запуск: ежедневный поиск, первые письма незнакомцам, лимит 20/день, прогрев ящика 2–3 недели.
6. Ежедневно: сводка, разбор ответов, правка писем и таргетинга. Метрики: найдено, отправлено, ответили, оффер, оплата.
