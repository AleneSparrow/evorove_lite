# Дополненный импорт Railway

Скрипт читает источники в read-only транзакциях. Доступ передаётся через
переменные процесса `OLD_ENGINE_DATABASE_URL`, `OLD_CRM_DATABASE_URL`,
`OLD_LEAD_DATABASE_URL`, `CLIENT_ZERO_BUSINESS_ID`; `.env` скрипт не читает.

```sh
.venv/bin/python scripts/import_from_railway.py --dry-run
# После проверки счётчиков; DB_PATH указывает на целевую SQLite:
.venv/bin/python scripts/import_from_railway.py --apply
# Только при решении перенести также лидов вне доски:
.venv/bin/python scripts/import_from_railway.py --apply --include-unboarded-leads
```

Dry-run не открывает целевую SQLite. По таблицам выводятся `read`, `transfer`,
`skip` и причины пропуска. `unboarded` — уникальные email вне доски. Приоритет
дедупликации: доска → Engine → Lead. Без флага они не переносятся.
`source_absent=1` означает отсутствие необязательной таблицы. Вывод содержит
только фиксированные названия и счётчики, без значений данных и секретов.

SMTP 465 заменяется на 587 со счётчиком `smtp_port_465_to_587`.
Пароли ящиков не читаются и не копируются: введите их заново в `/app/settings`.
Переносятся IMAP UID, настройки ящика и окончание подписки. Импорт сам не
включает отправку писем. Полные email из Engine имеют приоритет перед сводкой
CRM; другие каналы не импортируются. Subject и Message-ID сохраняются при
наличии в записи/metadata; отсутствующие поля не выдумываются. У исходного
письма `cold:` subject выделяется из сохранённого текста по старому формату.
Заметки переносятся в `log` с `event='note'` и ID для защиты от повторов.

Импорт сохраняет business ID и записывает соответствие в `legacy_business_map`.
Старая отписка использует эту таблицу: чужой или ещё не импортированный business
ID не принимается. GET показывает подтверждение, POST применяет отписку
(включая one-click без CSRF), повторный POST безопасен. Наличие карточки
человека для этой отписки не требуется.

Уточнение описи: старый `src/persistence/email_outreach_service.py` использует
base64url(JSON `[business_id, email]`) + первые 32 hex-символа HMAC-SHA256
с ключом `unsubscribe:` + значение `ACCOUNT_SECURITY_ENCRYPTION_KEY`, не Fernet.
Необязательная `LEGACY_ACCOUNT_SECURITY_ENCRYPTION_KEY` должна содержать это
старое значение. В Git оно не добавляется. В `deploy/checks.py` ключ явно
необязательный. Если ключ отсутствует или ссылка не распознана, оба метода
возвращают страницу с просьбой ответить STOP и HTTP 400.
Для старых писем домен `api.evorove.com` должен направлять путь отписки на
новый сервис — это отдельный шаг переключения.
